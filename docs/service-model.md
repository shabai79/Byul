# Byul 서비스 설계: 가장 이상적이고 법적으로 안전한 구조

> 법률 자문이 아닌 기획 문서입니다. ★ 표시는 출시 전에 변호사·세무사 확인이 필요한 부분입니다.

## 1. 한 문장 정의

**Byul은 물건을 잃어버린 사람이, 그 장소에 가는 사람에게 "찾으러 가는 일"을 맡기는 의뢰 플랫폼이다.**

"주운 사람이 사례금을 받는 곳"이 아니라 **"찾으러 가는 수고를 사고파는 곳"**으로 정의합니다. 이 차이가 법적 안전성의 핵심입니다.

| | 피해야 할 구조 | Byul의 구조 |
|---|---|---|
| 돈을 받는 사람 | 물건을 **주운** 사람 | 물건을 **찾으러 가는** 사람(도우미) |
| 돈의 성격 | 습득물 반환 대가 → 유실물법 보상금(5~20%)과 충돌, "돈 주면 돌려줄게" 흥정 위험 | **찾기 대행 수고비** (문의·방문·수령·발송이라는 노동의 대가) |
| 물건의 경로 | 주운 사람 → 분실자 직거래 | 경찰·분실물센터에 보관된 물건을 **위임을 받아 대신 수령** |
| 주운 사람의 역할 | 거래 당사자 | **습득 알림**만 가능(어디에 맡겼는지 알림), 돈은 오가지 않음 |

## 2. 사용자와 흐름

### 등장인물
- **분실자**: 해외·국내에서 물건을 잃어버린 사람
- **도우미**: 그 장소에 사는 사람, 출장·여행으로 갈 예정인 사람, 현지 교민
- **습득자**: 물건을 직접 주운 사람 (돈을 받지 않는 정보 제공자)
- **기관**: 경찰, 공항·역·호텔·박물관 분실물센터, 대사관

### 흐름 (사이트에 구현됨)
1. **분실 글 등록** (3단계): 무엇을 → 어디서 → 사진·이야기·성공 사례금
   - **확인 정보**(일련번호, 숨은 특징)는 비공개로 저장 → 결제한 도우미에게만 공개
   - 여권·반려동물은 기관 신고 안내가 먼저 뜸
   - 이용 규칙 동의 필수
2. **도우미의 제안**: 방문 예정일 · 맡을 일(문의만 / 문의+수령·발송) · **기본 수고비**
3. **분실자가 제안 선택** → 기본 수고비 + 성공 사례금 + 배송비 + 수수료를 **결제대행사에 예치**
4. **도우미가 기관에 문의**
   - 찾음 → 보관처·접수번호 기록 → (수령·발송) → 분실자 수령 확인 → **기본 수고비 + 성공 사례금 지급**
   - 못 찾음 → 분실자 확인 → **기본 수고비만 지급**, 나머지는 환불
5. **습득자**는 "이 물건을 주웠어요" → 경찰·시설 제출 안내 → 맡긴 곳만 분실자에게 알림 (거래 버튼 없음)

### 왜 "기본 수고비 + 성공 사례금"인가
- 도우미는 못 찾아도 시간과 교통비를 썼으므로 최소한의 대가를 받아야 참여합니다.
- 분실자는 찾았을 때만 큰돈을 내므로 부담이 적습니다.
- 돈의 성격이 "물건값"이 아니라 "노동의 대가"임이 구조로 드러나 법적 설명이 쉬워집니다.

## 3. 법적 체크리스트

| 항목 | 위험 | Byul의 대응 | 출시 전 할 일 |
|---|---|---|---|
| 유실물법·점유이탈물횡령 | 주운 사람이 사례금을 조건으로 반환을 미룸 | 습득자는 돈을 받을 수 없음(습득 알림), 경찰·시설 제출 안내 | ★ 대행 수고비 구조가 보상금 규정과 충돌하지 않는지 확인 |
| 통신판매중개 (전자상거래법) | 개인 간 유료 서비스 중개 | 화면 바닥·약관에 "중개자이며 거래 당사자 아님" 고지 | 사업자등록, **통신판매업 신고**, 중개자 고지 의무 확인 |
| 돈 보관 (전자금융거래법) | 회사가 직접 돈을 맡으면 전자금융업 등록 필요 가능 | 결제대행사의 에스크로·지급대행 상품 사용 전제 | ★ PG 계약 구조(토스페이먼츠 지급대행, Stripe Connect 등) 확인 |
| 위치정보법 | 기기 위치 수집 시 위치기반서비스 신고 | 현재 위치는 **브라우저 안에서만** 계산, 서버로 보내지 않음(테스트로 보장) | 위치 알림 등 기능 확대 시 방미통위 신고 |
| 개인정보보호법 | 신분증 사본·위임장 등 민감정보 | 연락처 자동 가림, 확인 정보 비공개 | **개인정보처리방침**, 신분증 사본은 보관 기간 최소화·암호화 |
| 세금 | 수고비 지급 시 원천징수 | 약관에 소득 신고 안내 | ★ 회사의 기타소득·사업소득 원천징수 의무 확인 (세무사) |
| 해외 법령 | 나라마다 습득물 규정·통관 다름 | 여권·현금·동물·배터리 직접 운송 금지 | 첫 진출 국가(일본 등) 규정 확인 |

## 4. 신뢰와 안전 (다음 단계로 구현할 것)

1. **본인인증**: 돈을 받는 도우미는 휴대폰 본인인증(PASS 등) 필수
2. **후기와 평점**: 거래 완료 후 서로 평가, 프로필에 "찾아준 횟수" 표시
3. **위임장 자동 생성**: 분실자 정보로 기관 제출용 위임장 PDF를 만들어 도우미에게 전달 (수령 시 대부분 필요)
4. **분쟁 처리**: 수령 확인 전 "물건이 달라요/파손됐어요" 신고 → 운영자 중재
5. **신고 기능**: 거짓 글, 외부 거래 유도, 흥정 시도 신고

## 5. 사업 모델

- **수수료**: 기본 수고비·성공 사례금 각각의 10% (현재 설정, `FEE_RATE`)
- **추가 수익**: 국제 배송 대행 연계, 분실물 글 상단 노출, 여행자 보험사 제휴(분실 보상 청구 서류 연계)
- **B2B**: 공항·호텔·관광지 분실물센터가 보관 중인 물건을 등록 → 주인과 자동 연결

## 6. 출시 순서 제안

1. **지금**: 체험판으로 주변 반응 확인, 법률 상담 1회 (이 문서와 `terms-draft.md`의 질문 목록 지참)
2. **1단계 (국내)**: 한국 안에서 먼저 운영 — 법이 명확하고 결제·본인인증 연동이 쉬움. 대중교통·공항·관광지 분실에 집중
3. **2단계 (일본)**: 한국인 여행객이 가장 많은 국가. 일본 유실물법도 경찰 제출·보상금 5~20%로 구조가 비슷
4. **3단계**: 유럽·동남아 주요 관광지, 현지 교민 도우미 확보

## 7. 사이트에 반영된 것 (이 저장소)

- 찾기 제안(방문일·맡을 일·기본 수고비), 받은 제안 목록, 제안 수락
- 기본 수고비 + 성공 사례금 에스크로, 찾음/못 찾음 분기, 정산·환불 계산 (`lib/mission.js`)
- 확인 정보 비공개 → 결제 후 도우미에게만 공개
- 습득 알림(돈이 오가지 않는 대화), 경찰·시설 제출 안내
- 이용 규칙(4개 언어), 등록 시 동의, 중개자 고지, 약관 초안(`docs/terms-draft.md`)
- 위치 비전송, 연락처 자동 가림
